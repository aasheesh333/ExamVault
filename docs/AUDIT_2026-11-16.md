## P0 — fix before the next release

### P0-1. Every text action is a dead button for screen readers

`app/lib/shared/widgets/ev_surfaces.dart:183-192`

```dart
return Semantics(
  container: true,
  excludeSemantics: true,   // ← drops the child's semantics, tap action included
  button: true,
  label: label,
  child: InkWell(onTap: onPressed, …),
);
```

`excludeSemantics: true` makes `visitChildrenForSemantics` return early, so the
`InkWell`'s `SemanticsAction.tap` never reaches the node, and the `Semantics`
widget was never given its own `onTap`.

**Verified, not inferred.** Probe output on this SDK (Flutter 3.47.9):

```
LABEL= ACTIONS=0
HAS_TAP=false
CTRL_TAP=true          # control: same tree without excludeSemantics
```

The resulting node is `flags: isButton, label: "Retry"` with **zero actions**.
TalkBack/VoiceOver announce "Retry, button", focus it, and double-tap does
nothing.

Affected call sites — this is the app's only text-action control:

| Where | Action that cannot be activated |
|---|---|
| `command_center_screen.dart:82` | "N saved" → Vault |
| `command_center_screen.dart:92` | **"Add" admit card** |
| `command_center_screen.dart:676`, `:1117` | vault / feed **Retry** |
| `instant_result_checker_screen.dart:439` | "Notice details" |
| `instant_result_checker_screen.dart:509` | "See live results" |
| `instant_result_checker_screen.dart:1469` | **"Try again"** (after a failed fetch) |
| `exam_calendar_screen.dart:435` | "Browse live results" |
| `admit_card_detail_screen.dart:1303` | "Retry" while the vault loads |

Same defect, five more sites (verified individually):

- `live_radar_tile.dart:231-245` — `_AlertBell`
- `exam_calendar_screen.dart:255-270` — calendar bell
- `exam_detail_sheet.dart:580-604` — "Alert me about this exam"
- `wallet_pass_card.dart:447-460` — `_CopyPill` ("Copy roll number"; it is a
  `GestureDetector`, so the node has *no* action at all)
- `whatsapp_share_card_screen.dart:757-770` — "Edit caption"

`a11y_matrix_test.dart` cannot catch this: `labeledTapTargetGuideline` only
inspects nodes that already have an action.

**Fix:** give the `Semantics` the action as well as the name —
`Semantics(container: true, excludeSemantics: true, button: true, label: label, onTap: onPressed, child: …)`.
For `_CopyPill`, add `onTap:` to the `Semantics`. Then add a matrix assertion:
`expect(node.getSemanticsData().hasAction(SemanticsAction.tap), isTrue)` for every
node flagged `isButton`. That is the only thing that stops this regressing.

### P0-2. The test suite is red — a time-bomb test, not a real regression

`app/test/live_feed_parsing_test.dart:109-124`

```
00:00 +5 -1: parsing liveCount only counts actionable statuses [E]
  Expected: <3>
    Actual: <2>
```

The fixture publishes `form_closing` at `2026-11-09T09:58Z` and relies on the
**default** 7-day TTL. That row expired at `2026-11-16T09:58Z`, so the test
started failing today, with no code change. `CI` runs `flutter test` and will go
red on the next push (and stays red forever after).

**Fix:** pin `expires_at` in the fixture (a far-future date) instead of depending
on `publishedAt + TTL`, or inject `now`. Any test that derives a verdict from
`DateTime.now()` + a default TTL is a future outage.

### P0-3. Renaming a card silently keeps the old exam id **and** the VERIFIED badge

`app/lib/features/vault/vault_form_sheet.dart:23-32`, used at `:339-343`

```dart
final fresh = match?.examId;
if (fresh != null && fresh.isNotEmpty) return fresh;
if (previous != null && previous.isNotEmpty) return previous;  // ← no name check
```

Edit "SSC CHSL 2026" → "UPSC CSE 2027" while that name has no published row: the
fresh match is null, so the card keeps `examId = ssc_chsl_2026` — while the same
form shows "No published result matches this name yet". Because
`keepsVerification` (`:371-375`) tests `base.examId == examId`, which is now
trivially true, the old `rollNumberVerified` survives too.

Consequences: "Check my result" searches the renamed card's roll against the
**old exam's** index, and the share card prints a green "IN THE LIST" for an exam
that was never checked. That is the exact failure class the checker's `ownRoll`
guard was written to prevent.

**Fix:** only reuse `previous` when the name is unchanged:

```dart
final renamed = base != null && _examName.text.trim() != base.examName.trim();
final examId = resolveExamId(
  examName: _examName.text,
  match: _match(watch: false),
  previous: renamed ? null : base?.examId,
);
```

and add `&& !renamed` to `keepsVerification`. The existing test ("keeps the
stored id when nothing is published") only covers the unchanged-name case, so it
still passes.

## P1 — wrong information shown to the user

### P1-1. The Alerts inbox says "Nothing needs your attention" while the feed is loading or dead

`app/lib/features/command_center/widgets/alerts_sheet.dart:52-63`, `:128-132`, `:179-188`

`alerts` is derived from `feedAsync.value?.feed`, so during a cold start
(`AsyncLoading`, no value) or a hard failure with nothing cached (`AsyncError`),
the list is empty and the sheet reports an all-clear — plus a paragraph
explaining why nothing is there. On result day with a dead network this is the
worst possible message, and it contradicts the radar's own `_FeedErrorCard`
(`command_center_screen.dart:1092`), which is honest about the same failure.

Note the file's own header comment only gated `markSeen` on this; the copy still
lies.

**Fix:** branch before the empty state —
loading → "Checking for updates…" + spinner; `hasError && !hasValue` → "Could not
check for updates." + Retry (`ref.invalidate(liveFeedProvider)`); only then the
current copy.

### P1-2. The Share tab can export a different exam than the one the user selected

`app/lib/features/share_card/whatsapp_share_card_screen.dart:140-156`

```dart
if (update != null) {
  for (final c in cards) { if (c.examId == update.examId) return c; }
  return null;                        // ← ignores selectedId entirely
}
```

`resultExamIdProvider` (a whole `LiveUpdate` frozen at tap time) outranks
`selectedCardIdProvider` unconditionally. It is cleared only by Home's card-open
and the vault dock's "Check my result"; swiping the vault pager writes only
`selectedCardIdProvider` (`admit_card_detail_screen.dart:204-208`).

So after any radar tap in the session: open Vault → swipe to card B → Share, and
you get card A's exam and roll. The preview is the only warning, and the
caption/roll switch then operate on A.

**Fix:** let an explicitly selected card win when its `examId` differs from
`update.examId`, and show which exam is being shared; or clear
`resultExamIdProvider` in the pager's `onPageChanged`.

### P1-3. The Share card is built from a frozen feed snapshot, so it goes stale

`app/lib/features/share_card/whatsapp_share_card_screen.dart:78`, `:105-106`, `:347`

`status`, `headline`, `officialUrl` and `pdfSizeLabel` all come from the tapped
`LiveUpdate` object, which is immutable and never refreshed. The checker screen
explicitly re-resolves from the fresh feed because "the row is a frozen
snapshot" (`instant_result_checker_screen.dart:207-220`); Share does not.

A row tapped while `awaited` still exports "UPDATE AWAITED" after the result
drops; a retired row still prints its old link into the PNG and the caption.

**Fix:** resolve by id on every build
(`feed.updates.firstWhereOrNull((u) => u.examId == pinned.examId) ?? pinned`), or
store only the exam id in the provider.

### P1-4. "Apply online" is the notice URL relabelled — the same link twice

`app/lib/features/calendar/exam_detail_sheet.dart:69-88`

`links` adds "Official website" for `officialPage`, then adds "Apply online" for
the **same** `officialPage` when the status is `notification`/`formClosing`.
`LiveUpdate` has no apply URL (`officialPdf` / `officialPage` only), so for those
rows the sheet shows one URL under two labels and the second promises an
application form the data never claimed — on a screen whose doc comment says
"no guess".

**Fix:** delete the third `_LinkRow`, or add an explicit `applyUrl` to the feed
and render it only when present.

### P1-5. The detail sheet mixes one exam's notice with another exam's card

`app/lib/features/calendar/exam_detail_sheet.dart:61-67`, `:264-300`

The sheet never checks `card!.examId == examId`. The checker passes both
unconditionally (`instant_result_checker_screen.dart:442`) and its `_targetCard`
falls back to `cards.first` when no saved card matches the tapped row — a case
the checker itself documents as reachable. The result is exam B's headline and
dates above a "Your card" panel containing exam A's roll number, centre and
report-by time.

**Fix:** compute `cardMatches = card != null && (examId == null || card.examId == examId)`
and gate both the "Exam date (your card)" row and the whole "Your card" section
on it (or retitle the section with the card's own exam name when it differs).

### P1-6. Vault form: every field is announced by its hint, never its name

`app/lib/features/vault/vault_form_sheet.dart:848-851`, `:871-880`

The visible label is a sibling `Text` above the field; the `TextFormField` only
has `hintText`. TalkBack therefore announces "As printed on your admit card, edit
box", "Street, area, city", "e.g. Gate 2" — never "Exam name", "Centre address",
"Gate", "Roll number". Twelve fields, indistinguishable.

The password show/hide `IconButton` (`:604-614`) has no tooltip and no
`semanticLabel`, so it is a bare "Button".

**Fix:** `InputDecoration(labelText: label, floatingLabelBehavior: FloatingLabelBehavior.never, hintText: hint)`
(keeps the current visual label), and `tooltip: _obscureSecret ? 'Show password' : 'Hide password'`.

### P1-7. The About sheet claims to show "the time each was last checked" and never does

`app/lib/features/about/about_sheet.dart:20-22` (the claim) vs `:415-451` (the code)

`SourceHealth.checkedAt` and `.homepage` are parsed and re-serialised but read by
**no widget** (`grep checkedAt lib/` → only the DTO/entity). The real feed carries
`checked_at` per source (SSC 2026-11-15T10:42Z, Railways 2026-11-15T10:44Z), and
the panel renders "unavailable" with no indication the observation is a day old.
On a stale cache this presents old health as current — the one thing the panel
exists to prevent. The "Official sources" links are also hand-maintained rather
than `source.homepage`.

**Fix:** render `source.checkedAt` next to the count ("17 items · checked 4h
ago"), and use `source.homepage` for the link row when present.

## P2 — layout, feedback and data-handling defects

### P2-1. Detail sheet overflows at 320 px @2.0× (measured: 10 px)

`app/lib/features/calendar/exam_detail_sheet.dart:380-417`

Probe at 320×568 @2.0×:

```
A RenderFlex overflowed by 10 pixels on the right.   (×3 rows)
```

`_DateRowView` is a `Row` with an `Expanded` label, an unbounded date `Text`, and
a hard `SizedBox(width: 76)` countdown. At 2.0× the non-flexible children exceed
the 248 px content width, so the label collapses to 0 and the countdown loses its
unit ("IN 30 …").

**Fix:** `Flexible` around the date, `FittedBox` (or drop) the fixed 76 px, and
stack the countdown under the label above ~1.4× — the same treatment
`EvSectionHeader` already got.

### P2-2. Alerts rows: the status pill eats the exam name at 2.0×

`app/lib/features/command_center/widgets/alerts_sheet.dart:249-271`

The pill is a non-flex `Row` child; at 2.0× "ADMIT CARD LIVE" takes ~230 of 248 px
and the `Expanded` name is squeezed to a sliver. `live_radar_tile.dart:130-140`
documents and fixes this exact defect with `Flexible` + `FittedBox`; the fix was
never mirrored here.

### P2-3. Sensitive clipboard wipe can destroy unrelated user data

`app/lib/core/utils/clipboard_service.dart:46-52`

The comment claims "any newer copy takes ownership … so it cancels the pending
wipe", but that only holds for copies made through `ClipboardService`. Copy a
password, switch to WhatsApp and copy a message within 60 s: the timer fires and
blanks the clipboard the user is now using. Android 10+ still permits background
clipboard *writes*, so this fires with the app in the background.

**Fix:** on fire, read and compare (`Clipboard.getData(kTextPlain)`) and skip if
the value is no longer ours; or make the wipe an explicit snackbar action.

### P2-4. A hung vault write traps the user in the form with no feedback

`app/lib/features/vault/vault_form_sheet.dart:156-157`, `:402-403`

Loads are bounded (10 s) but writes are not: `save()` → `_enqueue` →
`readIndex()` / `writeRaw()` / `writeIndex()` are raw Keystore calls. If one
hangs (the OEM failure the repository's own comments describe), `_saving` stays
true forever, the primary button is a permanent spinner, and Cancel / back /
barrier tap all hit `if (_saving) return;` silently.

**Fix:** `await save(card).timeout(const Duration(seconds: 15))` inside the
existing try/catch so `_error` + Retry appear, and make `_requestClose` during a
save say "Still saving…" rather than swallowing the tap.

### P2-5. The exported share card has no maximum width

`app/lib/features/share_card/whatsapp_share_card_screen.dart:424-427`

The `RepaintBoundary` is a direct child of a full-width `ListView`. The class
doc promises "1080 px wide … under 200 KB", which only holds at ~360 dp × 3.
On a 430 dp phone the export is 1194 px; in a desktop-web window it is ~2300 px
(~27 MB bitmap at capture), and the retry loop silently downgrades to 2×/1×.
Type is fixed-size, so the wide export also looks wrong.

**Fix:** `Center(child: ConstrainedBox(constraints: BoxConstraints(maxWidth: 400), child: RepaintBoundary(…)))`
and derive `pixelRatio` from the laid-out width (`(1080 / cardWidth).clamp(1, 3)`).

### P2-6. Share-text fallback reports success when the user cancelled

`app/lib/features/share_card/whatsapp_share_card_screen.dart:322-327`

`shareText` returns a `ShareResult`; the snackbar is unconditional, so a
dismissed sheet (or `ShareResultStatus.unavailable`) still says "shared the
message text instead".

**Fix:** branch on `result.status == ShareResultStatus.success`.

### P2-7. `ClipboardService.copy` has no failure path

`app/lib/core/utils/clipboard_service.dart:35-59`

`Clipboard.setData` can throw (web permission/gesture, channel error). It is
unguarded, so the exception escapes an `async onPressed`, no toast appears, and
the haptic never runs — the silent failure the class exists to prevent. The
empty-value branch also toasts before checking `context.mounted`.

### P2-8. Duplicate detection silently does nothing while the vault is opening

`app/lib/features/vault/vault_form_sheet.dart:345-351`

`.value ?? const []` means the duplicate check is skipped while the Keystore read
is in flight (Add is deliberately available then). A cold-start Add can save the
same exam + roll twice. Long-term, uniqueness belongs in
`AdmitCardsNotifier.save`, not only in the form.

### P2-9. Validation and save failures are visual-only

`app/lib/features/vault/vault_form_sheet.dart:647-709`

Neither `_validationNotice` nor `_error` is a live region, and focus is not moved
to the offending field. A screen-reader user taps "Save to vault" and hears
nothing. The checker already announces its verdicts
(`instant_result_checker_screen.dart:237-247`); reuse that.

### P2-10. "Choose the exam date" tells the user to find a field that is off-screen

`app/lib/features/vault/vault_form_sheet.dart:286-307`, `:323-330`

`_revealFirstInvalidField` knows only `_examNameFieldKey` and `_rollFieldKey`. The
date is a hard save blocker five rows above Save, so on a phone it is not
visible; the app says "tap the field above" and focuses nothing.

**Fix:** give `_DateField` a key and `Scrollable.ensureVisible` it like the text
fields.

### P2-11. "Copy official link" is ellipsised into nonsense at large text

`app/lib/features/share_card/whatsapp_share_card_screen.dart:689-720`

A fixed `SizedBox(width: 88)` with `maxLines: 2`. With the default empty
`EV_WEB_BASE`, the label is "Copy official link": at 1.35× it renders "Copy /
official…", at 2.0× "Copy / officia…". The tile's whole purpose is lost.

### P2-12. Section headings still cut at 2.0× when there is no trailing widget

`app/lib/shared/widgets/ev_surfaces.dart:103-120`

`stacked = trailing != null && scale > 1.4`, so headings without a trailing
action keep `maxLines: 1`. At 320 px @2.0× "WHERE THE DATA COMES FROM" and "WHY
WE NEVER HOST THE PDF" both ellipsise. (`sheets_test.dart:181` only asserts no
exception.)

**Fix:** wrap regardless of `trailing`.

### P2-13. Official-link rows in the detail sheet are not announced as links

`app/lib/features/calendar/exam_detail_sheet.dart:481-484`

`about_sheet.dart:462-467` deliberately wraps the equivalent row in
`Semantics(link: true, …)` ("Opens in a browser, so the honest trait is link, not
button"). The detail sheet's `_LinkTile` gets only the implicit tap action, so
TalkBack reads a plain text row.

### P2-14. The detail sheet's "link failed → copied instead" fallback is invisible

`app/lib/features/calendar/exam_detail_sheet.dart:494-500`

`ClipboardService` uses `ScaffoldMessenger.of(context)`, and inside this sheet
that resolves to the root messenger, whose SnackBar renders **behind** the modal
barrier and the 72 %-tall sheet. `about_sheet.dart:46-56` documents and fixes
exactly this; the detail sheet never got the same treatment.

### P2-15. About / detail sheets can be stacked by a double tap

`app/lib/features/command_center/command_center_screen.dart:282-286`,
`exam_calendar_screen.dart:56-60`

The bell got a synchronous `_alertsOpen` guard for precisely this reason
(`:155-179`: the barrier appears a frame after `showModalBottomSheet`). About and
the detail sheet have no equivalent, so a fast double tap stacks two identical
sheets.

## Half-finished features / dead code

1. **"Delete all data" does not exist.** `SecureVaultStore.wipe()`
   (`secure_vault_store.dart:169-178`) and `AdmitCardRepository.wipe()`
   (`admit_card_repository.dart:240-247`) are documented as "Used by 'Delete all
   data'" but have **no caller** and no UI. If wired as-is it would also leave
   the Hive settings (`theme`, `exam_alerts`, `alerts_seen_at`) and the cached
   feed behind, so it would not be the "everything" its name implies.
2. **Notification categories are promised but not choosable.** The About sheet
   says a push token is used "for the categories you follow"
   (`about_sheet.dart:561-565`), while `docs/PRIVACY.md` correctly states there is
   no picker and every device subscribes to all five
   (`main.dart:144`). Pick one: build the picker or fix the copy.
3. **`EvStatusPill`'s unnamed constructor is dead and would throw.**
   `status_pill.dart:13-20` has zero call sites; with no `color` it dereferences
   `_status!` on null (`:57`). `pillColor` (`:140`) is also uncalled, yet its
   comment still says `live_radar_tile.dart` "still calls it" — that file now
   uses `accentOn(context)`. Delete both.
4. **Unused API surface** (zero callers in `lib/` or `test/`): `CdnClient.peek`,
   `CdnClient.evictAll`, `ResultIndexRepository.pdfBytes`, `.pdfUrl`,
   `.clearMemo`, `LiveUpdate.countBy`, `.isNewerThan`, `LiveUpdateFormatting.relativeAge`,
   `.cdnPdfPath`, `.cdnRollIndexPath`, `primaryCardProvider`,
   `ExamCategoryFilter`. Some are deliberate seams; the ones that are not should
   go, because each one is a future false lead.
5. **Play submission is blocked on assets.** `docs/PLAY_STORE.md` still lists the
   1024×500 feature graphic as "still to make", and screenshots as "must be
   captured … from a real device build".
6. **`app/android/app/build.gradle.kts:27`** still carries Flutter's scaffold
   `TODO: Specify your own unique Application ID` above a real, shipped
   `applicationId`.
7. **`app/android/app/build.gradle.kts:37`** says `minSdk = 23 // Android 6.0`,
   but `flutter.minSdkVersion` is **24** (Android 7.0). The comment is wrong, and
   `docs` should match.
8. **`design/index.html`** is an archived exploratory deck. It is correctly
   banner-labelled "ARCHIVED — NOT SPEC", so this is a note, not a defect.

## UI/UX improvements worth doing next

Ordered by user value per hour of work.

1. **Per-exam alert entry point is inconsistent.** Home and Dates show a bell per
   row; the detail sheet shows one; the Alerts inbox rows are tap-only. A single
   long-press or trailing bell on an alert row would make "stop telling me about
   this" reachable from where the noise arrives.
2. **The radar has no "what changed since I last looked" marker.** The badge
   counts new rows, but the list itself gives no divider between seen and unseen.
   A hairline + "NEW" chip at the `alertsSeen` boundary would make the badge
   legible.
3. **Search has no result summary for the vault.** The radar header says "3 of
   34"; the vault section says nothing when a query narrows it, and the empty
   state is the only feedback.
4. **`fontSize: 10` in live UI contradicts the design system's own floor.**
   `theme_tokens.dart:11` says body text never goes below 11 px;
   `exam_detail_sheet.dart:410` and `exam_calendar_screen.dart:392` both ship 10.
   (The `share_infographic.dart` 9 px values are fine — that is a 3× bitmap.)
5. **Dates tab has no grouping.** Entries are a flat list; "This week / This
   month / Later" headers would make a 20-row calendar scannable, and the
   `ExamCalendarScreen` already sorts by date.
6. **Web manifest is missing `id`.** `app/web/manifest.json` has no `id`, so the
   installed app's identity is derived from `start_url`. A stable `"id": "/"`
   keeps the install identity across a future start-URL change (see the
   `install-web-app` guidance). `theme_color` also cannot express both schemes —
   the per-scheme `<meta name="theme-color">` in `index.html` is the correct
   workaround and is already in place.
7. **iOS display name casing.** `app/ios/Runner/Info.plist` sets
   `CFBundleDisplayName` to `Examvault` (lower-case v) while every other surface
   says `ExamVault`. Also, iOS declares landscape support for a portrait-designed
   app whose web manifest says `portrait-primary`; lock it or support it.
8. **`docs/PLAY_STORE.md` short description** should be re-verified against the
   Console limit at submission time; it is 79 characters today, so any edit can
   push it over 80.
